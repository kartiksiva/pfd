# Technical Review Report: Milestone T1.1 - T2.1
**Project:** Process Documentation Agent (MVP)

**Status:** **NO-GO** (Critical Blockers Identified)

## 1. Executive Summary
The initial project scaffolding (FastAPI, Next.js shell, Docker) is solid. However, the implementation of the core data model and ingestion pipeline deviates from the established API contract and introduces security risks. Milestone **T2.2 (Async Processing)** cannot proceed until these architectural and security foundations are corrected.

---

## 2. Critical Blockers (Severity: HIGH/CRITICAL)

### [CRITICAL] Finding 1: API/Database Contract Mismatch
- **Files:** `backend/app/models.py`, `backend/app/repository.py`, `backend/app/main.py`
- **Reference:** `openapi.yaml` (JobRecord), `schemas.md`
- **Description:** The `JobRecord` model in the database and the API response for `GET /api/jobs/{id}` are missing required fields.
- **Impact:** Breaks frontend integration and fails OpenAPI validation. Blocks `T2.2` orchestration logic.
- **Missing Fields:**
  - `model_plan` (JSON object)
  - `limits_applied` (JSON object)
  - `usage_cost_estimate` (JSON object)
- **Proposed Fix:** 
  1. Add columns for these fields to `JobRecord` in `models.py`.
  2. Update `repository.py:create_job` to initialize them with valid (empty) schemas.
  3. Ensure `main.py` serializes these fields in the job response.

### [HIGH] Finding 2: Unsafe Filename Handling (Path Traversal Risk)
- **Files:** `backend/app/upload_validation.py`
- **Reference:** `validate_and_persist_inputs` (Lines 92, 107, 122)
- **Description:** Uploaded filenames are used directly to construct disk paths: `path = job_dir / (file.filename)`.
- **Impact:** Malicious filenames (e.g., `../../etc/passwd`) could allow writing outside the `UPLOADS_DIR`.
- **Proposed Fix:** Sanitize all filenames using `os.path.basename()` or `Path(file.filename).name` before path concatenation.

### [HIGH] Finding 3: Lack of Cleanup on Validation Failure
- **Files:** `backend/app/upload_validation.py`
- **Reference:** `validate_and_persist_inputs`
- **Description:** If a multi-file upload fails partway (e.g., first file passes, second file fails MIME check), the first file is left on disk.
- **Impact:** Causes storage leaks and inconsistent state for failed jobs.
- **Proposed Fix:** Implement a `try...except` block in `validate_and_persist_inputs`. If any validation fails, recursively delete the `job_dir` before raising the `ValidationError`.

## 3. Medium & Low Severity Findings

### [MEDIUM] Finding 4: Inconsistent API Response Envelopes
- **Files:** `backend/app/main.py`
- **Description:** Errors are manually returned as `JSONResponse` objects, while successes use `ApiEnvelope`.
- **Impact:** Higher risk of deviating from the `success/data/error` contract in future endpoints.
- **Proposed Fix:** Use a helper function or a custom FastAPI Exception Handler to ensure every response (including errors) is wrapped in a validated `ApiEnvelope` Pydantic model.

### [LOW] Finding 5: Unbounded String Inputs
- **Files:** `backend/app/main.py`, `openapi.yaml`
- **Description:** The `context_notes` field in `POST /api/jobs` has no character limit.
- **Impact:** Potential for resource abuse or prompt injection.
- **Proposed Fix:** Define a `maxLength` (e.g., 2000 chars) for `context_notes` and enforce it at the API layer.

## 4. Re-Review Requirements
Approval to proceed to **Milestone T2.2** is contingent upon:
1. **Model Synchronization:** Full compliance with `openapi.yaml` for all `JobRecord` fields.
2. **Security Certification:** Safe filename handling and traversal prevention.
3. **Atomic Ingestion:** Automatic purging of partial uploads on failure.
4. **Schema Validation:** The `GET /api/jobs/{id}` response must pass a strict schema check against the documentation.
